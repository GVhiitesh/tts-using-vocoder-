# tts-using-vocoder-
# Qwen3-TTS Backbone: Text-to-Audio Token Generation

## 1. Project Overview

This project explores the backbone of the Qwen3-TTS text-to-speech model. The primary objective is to generate and extract intermediate audio tokens from input text before decoding them into speech.

The notebook uses the **Qwen3-TTS 0.6B CustomVoice model** to examine the text-to-audio generation process, decode the generated tokens, and compare the results with the model's official speech-generation pipeline.

## 2. Objectives

- Understand the text-to-speech generation pipeline.
- Load and run the Qwen3-TTS model.
- Extract intermediate audio tokens generated by the backbone.
- Decode the extracted tokens into an audio waveform.
- Compare the extracted-token output with the official generation pipeline.
- Provide a foundation for further experimentation with the speech-generation backbone.

## 3. Model and Technologies

- **Model:** `Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice`
- **Framework:** PyTorch
- **Model library:** `qwen-tts`
- **Programming language:** Python
- **Execution environment:** Google Colab
- **Hardware:** CUDA-compatible GPU
- **Audio processing:** SoundFile

## 4. System Architecture

The notebook follows this general pipeline:

`Input Text → Prompt Construction → Tokenization → Qwen3-TTS Backbone → Audio Tokens → Audio Decoder → Generated Speech`

### Step 1: Input Processing

The input text is prepared using the model's prompt-building and tokenization utilities. The notebook also specifies the language and speaker used for speech generation.

### Step 2: Backbone Generation

The notebook calls the underlying model's generation method to obtain intermediate audio-token tensors. The `backbone()` function is the main component responsible for this stage.

### Step 3: Audio Token Extraction

The generated tensors are returned separately from the decoding stage. This makes it possible to inspect the intermediate representations and reuse them in subsequent experiments.

### Step 4: Audio Decoding

The extracted audio tokens are passed to the model's speech tokenizer and decoder to reconstruct an audio waveform.

### Step 5: Comparison with the Official Pipeline

The notebook also uses the higher-level `generate_custom_voice()` method to generate speech from the same input. The resulting audio can be compared with the output reconstructed from the extracted tokens.

## 5. Notebook Structure

The notebook contains the following stages:

1. **Environment Setup:** Installs the required packages and checks GPU availability.
2. **Model Loading:** Loads the Qwen3-TTS model and configures the speaker and language.
3. **Model Inspection:** Examines tokenization, prompt construction, and internal model components.
4. **Backbone Implementation:** Defines the `backbone()` function to generate and return intermediate audio tokens.
5. **Token Decoding:** Passes the extracted tokens to the decoder to generate speech.
6. **Pipeline Comparison:** Generates speech using the official API for comparison.

## 6. Expected Outputs

When the relevant notebook cells execute successfully, the notebook generates the following audio files:

| File | Description |
|---|---|
| `correct_tokens_output.wav` | Audio reconstructed from an earlier diagnostic test |
| `backbone_output.wav` | Audio reconstructed from tokens returned by the backbone function |
| `official_pipeline_output.wav` | Audio generated through the official CustomVoice pipeline |

The notebook also displays token information, tensor shapes, data types, and execution timings for selected operations.

## 7. How to Run the Notebook

1. Open the notebook in Google Colab.
2. Select **Runtime → Change runtime type → T4 GPU**, or another compatible GPU.
3. Run the setup cell and confirm that CUDA is available.
4. Execute the model-loading cell and wait for the model to load.
5. Run the relevant diagnostic and backbone implementation cells.
6. Execute the backbone function with the desired text, speaker, and language.
7. Pass the returned audio tokens to the decoder.
8. Play the generated audio and run the official pipeline comparison.

A GPU-enabled runtime, compatible PyTorch installation, sufficient GPU memory, and internet access for model downloads are required.

## 8. Implementation Notes

The notebook uses internal model methods for prompt construction, tokenization, and generation. These methods may change between library versions.

The notebook should be executed in the correct cell order. In particular, diagnostic cells that depend on `audio_tokens` must be run only after that variable has been defined.

## 9. Completion Criteria

The implementation should be considered runtime-verified after confirming that:

- The model loads successfully on the GPU.
- The backbone returns non-empty audio-token tensors.
